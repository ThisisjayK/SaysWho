Install and use

Five steps to a marked answer.

Capture needs nothing but the extension. Verdicts need a local server and a free API key, and both are below.

Download the archive

Chrome or any Chromium browser. Python 3.11 or newer for the server.

  1. Download and unzip

    You get a folder called sayswho with four things in it: the extension/ itself, the Python auditor in sayswho/, the frozen query set the server hash-checks before it will start, and the two scripts that do that check. Put it wherever you keep projects.

  2. Load the extension

    It ships unpacked, so it installs from Chrome's own extensions page. There is no store listing and no review queue.

    1. Open chrome://extensions.
    2. Turn on Developer mode, top right.
    3. Click Load unpacked, top left.
    4. Select the extension folder inside the unzipped project. Not the project root, and not extension/src.
    5. Pin it to the toolbar so the popup is one click away.

    Reload any tab you had open before installing. A tab loaded earlier is running no content script, and the on-page buttons will not appear on it.

  3. Capture an answer

    Open a supported product, ask something that produces citations, then click Capture. You get the answer text, its SHA-256 and every cited URL written to a file. No key, no server, and no network calls beyond the page you are already on.

    Supported today: chatgpt.com, claude.ai, perplexity.ai, and Google search results.

  4. Start the local server

    Fetching cited pages and judging claims happens outside the browser. Verdicts need this running.

    cd sayswho
python3 -m venv .venv
.venv/bin/pip install google-genai
export GEMINI_API_KEY=paste-your-real-key
.venv/bin/python -m sayswho.server --judge

    A free key comes from aistudio.google.com. It is read from the environment and never written to a file. The server binds to 127.0.0.1 only, and it will not start if the key is missing or the provider rejects it, so a green light in the popup means it genuinely works.

    Substitute your real key on that fourth line. Pasting a placeholder verbatim exports the literal string and is the most common way this fails.

  5. Audit

    Click Audit. The capture is posted to the local server, which fetches every cited page, judges each claim against it, confirms each quoted span really appears in the fetched document, and draws the marked answer in a panel over the page.

    It takes as long as it takes. Two runs were timed: 22 seconds, and about five minutes on a rate-limited free tier. Two observations are not a benchmark, so do not plan around either number.

Controls

What each button does

Capture

Works offline, needs no key. Reads the answer, hashes it, extracts every citation, counts the ones it could not reach, and writes the record to your downloads folder.

Useful when you want the record now and the verdicts later, or when you are collecting answers to audit as a batch.

Audit

Needs the local server. Does everything Capture does, then sends the record to 127.0.0.1:8765 instead of downloading it, and renders the marked answer.

The server saves the capture and the report into the project folder, so nothing lands in your downloads twice.

Buttons on the page

A checkbox in the popup. Shows or hides the two floating controls at the bottom right of the page. Both actions stay available from the popup either way.

If unticking it does nothing, that tab is running a content script from before your last extension reload. Reload the tab.

Audit server running

Not a button. A live status dot. Green means the local server answered a health check and Audit will work. Grey means you get Capture and nothing else.

The warning worth reading

After a capture the popup may say 2 "+N" control(s) hide 2+ citations. Expand them and capture again. Products collapse some citations behind an expander. The extension counts what it could not reach instead of reporting a clean number it has not earned. Across ten measured answers at least 20 of 53 claim-attached citations were hidden this way. An audit built on a capture carrying that warning covers part of the answer, and the report says so on its face.

Files

What it writes, where, and why

Two files per capture, both going to your browser's normal download location. Nothing is uploaded anywhere.

FileWhereWhy it exists
capture-<product>-<time>.json Downloads/sayswho/ The record: answer text, its hash, every cited URL, and the count of what could not be reached. This is what the pipeline reads. Audit does not write it, because the server has already saved it into the project.
sayswho-page-<product>-<time>.html Downloads/ The page exactly as it stood at capture time. Both buttons write it. It is what allows the extraction to be re-run and checked against a second implementation later.

Keeping the page matters more than it looks. An adapter can only be checked against a stored page, and that chance has already been lost once here: 29 captures from one product point at page files that are no longer on disk, so that adapter can never be verified after the fact. The archived page is the evidence.

A stored page is a whole application shell. On some products that includes a sidebar listing your other conversations. It stays on your machine, and the project ignores these files by name so they cannot be committed by accident.

The archive

What is in the download

211 KB, 54 files, built from an allowlist of what the tool needs at runtime. Three gates run before anything gets written.

  • No keys. The build aborts if any file matches a key-shaped pattern.
  • No personal data. Contact addresses become a placeholder, home directory paths become ~, and every substitution is printed while the archive is built so the scrub is never silent.
  • No captured data. Stored pages, fetch caches, captures, splits, gold sets, run records and reports are all excluded. They carry answer text and quoted page passages, and those stay on the machine that produced them.
  • Nothing that does not run. No video, no tests, no working notes, no project write-ups. The allowlist is four entries long and every one of them is read at runtime, which is how a missing import was caught: the first build shipped a server that could not start.

SaysWho is research software. You run it by hand, for as long as an audit takes, and it is not something to leave running.
